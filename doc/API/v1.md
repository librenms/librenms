# API v1 (Beta)

!!! warning "Beta"
    The v1 API is in **beta**. Endpoints and behaviour may change without
    notice while it is under active development. Full endpoint documentation
    is coming later — for now this page covers the basics and how to extend
    it. The stable, fully documented API remains [v0](index.md).

    The v1 API is disabled by default. Enable it with
    `lnms config:set api.v1.enabled true`, or in the web UI under
    **Settings → API → API v1 (Beta)**. When disabled, all `/api/v1`
    endpoints return 404.

## Overview

The v1 API is served under the `/api/v1` prefix and is built on
[Laravel Restify](https://restify.binarcode.com/) with
[Sanctum](https://laravel.com/docs/sanctum) bearer-token authentication.

## Authentication

Most v1 endpoints require a personal access token sent as a standard Bearer token:

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' https://librenms.org/api/v1/system
```

Create an API token from the web interface at `/api-access/` (**Settings → API Settings → API Access**). Note that `X-Auth-Token` is only supported on API v0 endpoints; API v1 strictly requires the `Authorization: Bearer` header.

## Available endpoints

| Method | Path             | Auth          | Description                                      |
|--------|------------------|---------------|--------------------------------------------------|
| `GET`  | `/api/v1/health` | none (public) | Rate-limited readiness probe.                    |
| `GET`  | `/api/v1/system` | bearer token  | Application version and database row statistics. |
| `GET`  | `/api/v1/devices/{device}/metrics/summary` | bearer token | Current CPU, memory, load, disk and network values from the poller's data. |
| `GET`  | `/api/v1/devices/{device}/metrics/realtime` | bearer token | The latest on-demand SNMP sample; `?refresh=1` takes a new one after answering. |
| `GET`  | `/api/v1/devices/{device}/metrics/live` | bearer token | One synchronous SNMP sample of every supported metric. |
| `GET`  | `/api/v1/devices/{device}/metrics/live/load` | bearer token | One synchronous SNMP sample of CPU and load only. |
| `GET`  | `/api/v1/devices/{device}/metrics/live/network` | bearer token | One synchronous SNMP sample of the interface counters. |
| `GET`  | `/api/v1/devices/{device}/metrics/io-wait` | bearer token | The current I/O wait percentage from the UCD CPU RRDs. |

More endpoints will be added as the v1 API matures.

### Health

`GET /api/v1/health` is public so it can report a failure even when
database-backed token authentication is unavailable. Its response is
deliberately generic: it does not identify dependencies or include exception
messages, application details, or user information. Requests are limited to
60 per minute per client.

A healthy response returns HTTP 200:

```json
{
  "meta": {
    "status": "healthy"
  }
}
```

An unavailable dependency returns a generic HTTP 503:

```json
{
  "errors": [
    {
      "status": "503",
      "title": "Service Unavailable",
      "detail": "A required service is unavailable."
    }
  ]
}
```

### System

`GET /api/v1/system` requires a bearer token. It returns application
identity and selected table row counts:

```json
{
  "meta": {
    "application": {
      "name": "LibreNMS",
      "version": "26.7.0"
    },
    "statistics": {
      "devices": 42,
      "ports": 512,
      "users": 3
    }
  }
}
```

If the database is unavailable during authentication or while gathering
statistics, the endpoint returns the same generic JSON:API 503 error used by
the health endpoint. Database connection details are never included.

### Device metrics

These endpoints give dashboards and mobile clients the *current* state of a
device without parsing graphs. `{device}` is a device id or hostname; the
caller must be allowed to view the device. Every response is
`{"data": {"device_id", "hostname", ...}}`.

`GET /api/v1/devices/{device}/metrics/summary` is a read-only snapshot of the
poller's database and the most recent RRD values, cached for 30 seconds. It
never initiates SNMP. `metrics` contains `cpu` (`value`, `user`, `system`,
`idle`, `steal`, percentages), `io_wait`, `memory` (`value` percent,
`used_bytes`, `total_bytes`, `cached_bytes`, `swap_used_bytes`), `load`
(`one`, `five`, `fifteen`), `disk` (`read_bytes_per_second`,
`write_bytes_per_second`, `read_iops`, `write_iops`, per-disk `devices`),
`network` (`in_bps`, `out_bps`) and `processor_count`; every block carries
`available` and `sampled_at`. Missing data is reported as unavailable rather
than as zero. `source` is `poller_database_rrd`.

`GET /api/v1/devices/{device}/metrics/realtime` returns the most recent
device-scoped SNMP sample from the cache without waiting for SNMP. With
`?refresh=1` the response is sent first and the worker then takes one counter
snapshot, so repeated lightweight reads form an on-demand sampler. Disk rates
need two snapshots at least three seconds apart; whole physical disks are
preferred over partitions and RAID or cache aliases, and up to 16 disks are
sampled. `database_network` carries the poller's interface rates as a fallback.
Clients must use each metric's `sampled_at`, not their request time.

`GET /api/v1/devices/{device}/metrics/live`, `.../live/load` and
`.../live/network` take one synchronous SNMP sample (all metrics, CPU and
load only, or the interface counters). One sample runs at a time per device;
a concurrent caller receives HTTP `429`. `network.interfaces` lists
`{port_id, name, in_bps, out_bps}` for the active, enabled, non-loopback
interfaces of the sample; rates are bits per second.

`GET /api/v1/devices/{device}/metrics/io-wait` answers
`{"data": {"metric": {"name": "io_wait", "available": true, "value": 3.2, "raw_value": 12.5, "unit": "percent", "timestamp": "…", "graph": "device_ucd_io_wait", "source": "ucd_cpu_rrd"}}}`
computed from timestamp-aligned UCD CPU state RRD samples, so multi-core raw
counters do not inflate the percentage. Missing or stale data is returned with
`available: false` and a `reason`.

## Adding custom endpoints

There are two places to add v1 functionality, depending on whether you
need a plain route or a full CRUD resource.

### 1. Custom (non-repository) endpoints

Routes that are not standard CRUD resources—health checks, actions,
reports, etc.—are declared by overriding `routes()` on a class in
`app/Restify/`. Restify discovers these classes and applies the configured
v1 prefix and middleware. Point the route at an invokable controller in
`app/Http/Controllers/Api/V1/`.

```php
// app/Restify/ExampleRepository.php
namespace App\Restify;

use App\Http\Controllers\Api\V1\ExampleController;
use Illuminate\Routing\Router;

class ExampleRepository extends Repository
{
    public static string $uriKey = '';

    public static function routes(Router $router, array $attributes, $wrap = true): void
    {
        // Routes are authenticated by default.
        $router->get('example', ExampleController::class)
            ->name('api.v1.example');

        // Authentication must be explicitly removed for a public route.
        $router->get('public-example', ExampleController::class)
            ->withoutMiddleware('auth:sanctum')
            ->name('api.v1.public-example');
    }
}
```

A minimal controller:

```php
// app/Http/Controllers/Api/V1/ExampleController.php
namespace App\Http\Controllers\Api\V1;

use App\Http\Controllers\Controller;
use Illuminate\Http\JsonResponse;

class ExampleController extends Controller
{
    public function __invoke(): JsonResponse
    {
        return response()->json(['meta' => ['message' => 'example']]);
    }
}
```

Guidelines:

- Place controllers in `app/Http/Controllers/Api/V1/`.
- Routes inherit `auth:sanctum`. Remove it with
  `->withoutMiddleware('auth:sanctum')` only for intentionally public
  endpoints such as the health probe.
- Give custom routes a unique `api.v1.*` name.

### 2. Restify repository (CRUD) resources

For standard create/read/update/delete access to a model, add a Restify
repository in `app/Restify/`:

```php
// app/Restify/DeviceRepository.php
namespace App\Restify;

use App\Models\Device;

class DeviceRepository extends Repository
{
    public static string $model = Device::class;
}
```

Restify discovers the repository and generates the standard resource routes
(index, show, store, update, destroy) under `/api/v1` automatically. See the
[Laravel Restify documentation](https://restify.binarcode.com/) for how to
define repositories, fields, and authorization.

### After changing routes

Route and config are cached on container start, so after adding or changing
endpoints clear the caches:

```bash
php artisan route:clear
php artisan config:clear
```

Verify the result with `php artisan route:list --path=api/v1`.
