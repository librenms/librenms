# API v1 (Beta)

!!! warning "Beta"
    The v1 API is in **beta**. Endpoints and behaviour may change without
    notice while it is under active development. Full endpoint documentation
    is coming later — for now this page covers the basics and how to extend
    it. The stable, fully documented API remains [v0](index.md).

    The v1 API is disabled by default. Enable it with
    `lnms config:set api.v1.enabled true`, or in the web UI under
    **Settings → API → API v1 (Beta)**. When disabled, all `/api/v1`
    endpoints return 404.

## Overview

The v1 API is served under the `/api/v1` prefix and follows
[JSON:API v1.1](https://jsonapi.org/format/1.1/). Responses use the
`application/vnd.api+json` content type. Request bodies must use it too, and no
JSON:API extensions are supported. Every document has `jsonapi.version` and,
except errors, a `links.self`. Developers adding endpoints should read
[API v1 development](../Developing/API-v1.md).

## Versioning

While v1 is in beta, any endpoint may change. Once it is final, changes that
could break a client get a new date-based version that clients opt into, and
clients that don't opt in keep the shape they were built against. Adding
attributes, relationships, endpoints or parameters is not a breaking change, so
clients must ignore members they don't know.

## Authentication

Most v1 endpoints require a personal access token sent as a standard Bearer token:

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' https://librenms.org/api/v1/system
```

Create an API token from the web interface at `/api-access/` (**Settings → API Settings → API Access**). Note that `X-Auth-Token` is only supported on API v0 endpoints; API v1 strictly requires the `Authorization: Bearer` header.

The token's user must have the `api.access` permission for every endpoint
except `/api/v1/health`. Beyond that, each resource is authorized with the
same permissions as the web UI.

## Available endpoints

| Method | Path                          | Auth          | Description                                      |
|--------|-------------------------------|---------------|--------------------------------------------------|
| `GET`  | `/api/v1/health`              | none (public) | Rate-limited readiness probe.                    |
| `GET`  | `/api/v1/system`              | bearer token  | Application version and database row statistics. |
| `GET`  | `/api/v1/devices`             | bearer token  | List devices.                                    |
| `GET`  | `/api/v1/devices/{id}`        | bearer token  | Show a device.                                   |
| `GET`  | `/api/v1/devices/{id}/ports`  | bearer token  | List the ports of a device.                      |
| `GET`  | `/api/v1/ports`               | bearer token  | List ports.                                      |
| `GET`  | `/api/v1/ports/{id}`          | bearer token  | Show a port.                                     |
| `GET`  | `/api/v1/ports/{id}/device`   | bearer token  | Show the device of a port.                       |
| `GET`  | `/api/v1/routing/isis-adjacencies`             | bearer token  | List IS-IS adjacencies.                     |
| `GET`  | `/api/v1/routing/isis-adjacencies/{id}`        | bearer token  | Show an IS-IS adjacency.                    |
| `GET`  | `/api/v1/routing/isis-adjacencies/{id}/device` | bearer token  | Show the device of an IS-IS adjacency.      |
| `GET`  | `/api/v1/routing/isis-adjacencies/{id}/port`   | bearer token  | Show the local port of an IS-IS adjacency.  |

More endpoints will be added as the v1 API matures.

## Fetching resources

Lists and records only contain what the token's user can see.

| Parameter | Example | Description |
|-----------|---------|-------------|
| `page[number]`, `page[size]` | `page[number]=2&page[size]=100` | Pagination. Default size 50, maximum 500. |
| `sort` | `sort=os,-hostname` | Comma separated, `-` for descending. |
| `filter` | `filter[os]=ios` | Exact match. |
| | `filter[search][contains]=core` | With an operator: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `contains`, `not_contains`, `starts_with`, `ends_with`, `is_empty`, `is_not_empty`, `in`, `not_in`. `in` takes a comma separated list. |
| `include` | `include=device` | Add related resources to `included`. |
| `fields` | `fields[devices]=hostname,os` | Only return these attributes. |

Other query parameters with only lowercase letters are reserved by JSON:API
and rejected. Booleans filter as `true` or `false`. Lists have `links` (`first`, `last`,
`prev`, `next`) and `meta.page` (`currentPage`, `lastPage`, `perPage`, `total`).

```json
{
  "data": [
    {
      "id": "12",
      "type": "ports",
      "attributes": { "name": "eth0", "operationalStatus": "up" },
      "relationships": {
        "device": {
          "links": { "related": "https://librenms.example.com/api/v1/ports/12/device" },
          "data": { "id": "3", "type": "devices" }
        }
      },
      "links": { "self": "https://librenms.example.com/api/v1/ports/12" }
    }
  ],
  "included": [
    { "id": "3", "type": "devices", "attributes": { "hostname": "core1.example.com" } }
  ],
  "links": { "self": "…", "first": "…", "last": "…", "prev": null, "next": null },
  "jsonapi": { "version": "1.1" },
  "meta": { "page": { "currentPage": 1, "lastPage": 1, "perPage": 50, "total": 1 } }
}
```

A relationship's `data` is only present when it is included. A related device
the user can't view is left out of `included`.

### Devices

Type `devices`. Relationship `ports`, a to-many relationship listed at its
related link.

| Attribute | Description |
|-----------|-------------|
| `displayName` | Name shown in the web UI. |
| `hostname` | Hostname or IP used to reach the device. |
| `ipAddress` | Resolved IP address. |
| `description`, `notes` | Description and notes entered in LibreNMS. |
| `systemName`, `systemDescription`, `systemContact` | SNMP system values. |
| `sysObjectID` | SNMP object identifier of the device model, such as `.1.3.6.1.4.1.9.1.1745`. |
| `isUp`, `statusReason` | Status, and why it is down. |
| `uptime` | Seconds. |
| `deviceType` | Device type, such as `network` or `server`. |
| `os`, `osVersion`, `osFeatures` | Detected operating system. |
| `hardware`, `serialNumber` | Detected hardware. |
| `bgpLocalAs` | Local BGP AS number. |
| `isMonitored` | Whether the device is polled, discovered and alerted on. False when the device is disabled. |
| `isIgnored`, `isStatusIgnored`, `isAlertingEnabled` | Alerting settings. |
| `lastPolledAt`, `lastDiscoveredAt`, `createdAt` | ISO 8601 timestamps. |
| `lastPollDuration`, `lastDiscoveryDuration` | Seconds. |

Sorts: `displayName`, `hostname`, `systemName`, `uptime`, `deviceType`, `os`,
`lastPolledAt`, `createdAt`.

Filters: `id`, `search`, `displayName`, `hostname`, `systemName`, `isUp`,
`deviceType`, `os`, `osVersion`, `osFeatures`, `hardware`, `isMonitored`,
`isIgnored`, `isAlertingEnabled`.

### Ports

Type `ports`. Relationship `device`, includable.

| Attribute | Description |
|-----------|-------------|
| `displayName` | Name shown in the web UI. |
| `name` | Interface name, such as `Gi0/1`. |
| `description` | Description configured on the device (ifAlias). |
| `ifIndex` | SNMP interface index. |
| `ifDescr` | The device's own description of the interface. Most devices report the interface name, some the hardware. |
| `interfaceType` | IANA interface type, such as `ethernetCsmacd`. |
| `administrativeStatus`, `operationalStatus` | `up`, `down`, `testing`, `unknown`, `dormant`, `notPresent` or `lowerLayerDown`. |
| `speed` | Bits per second. |
| `duplex` | Duplex mode. |
| `mtu` | Bytes. |
| `macAddress` | Interface MAC address. |
| `untaggedVlan` | Untagged VLAN: the access, native or PVID VLAN. |
| `trunkEncapsulation` | VLAN trunk encapsulation, such as `dot1Q`, when the port is a trunk. |
| `isPollingEnabled`, `isIgnored`, `isDeleted` | Polling and alerting settings, and whether the port is gone from the device. |
| `lastPolledAt` | ISO 8601 timestamp. |

Sorts: `name`, `description`, `ifIndex`, `ifDescr`, `interfaceType`,
`administrativeStatus`, `operationalStatus`, `speed`.

Filters: `id`, `search`, `device` (device id), `name`, `description`, `ifIndex`,
`ifDescr`, `interfaceType`, `administrativeStatus`, `operationalStatus`, `speed`,
`duplex`, `mtu`, `macAddress`, `untaggedVlan`, `isPollingEnabled`, `isIgnored`, `isDeleted`.

Traffic and other metrics are not port attributes, they will be available under
`/api/v1/metrics`.

### IS-IS adjacencies

Type `isis-adjacencies`, grouped with the other routing resources under
`/api/v1/routing`. Relationships `device` and `port`, both includable. The data
is read-only.

| Attribute | Description |
|-----------|-------------|
| `index` | IS-IS circuit index. |
| `ifIndex` | SNMP interface index of the local port. |
| `circuitAdministrativeStatus` | Administrative state of the circuit, such as `on` or `off`. |
| `state` | Adjacency state, such as `up`, `down` or `initializing`. |
| `neighborSystemType` | Neighbour system type: `L1`, `L2`, `L1L2` or `unknown`. |
| `neighborSystemId` | Neighbour system ID. |
| `neighborPriority` | Neighbour priority for the adjacency. |
| `lastUpTime` | Device uptime, in seconds, when the adjacency last came up. |
| `neighborAreaAddress` | Neighbour area address. |
| `neighborIpAddressType` | Neighbour IP address type, such as `ipv4` or `ipv6`. |
| `neighborIpAddress` | Neighbour IP address. |

Sorts: `ifIndex`, `state`, `neighborSystemId`, `neighborIpAddress`.

Filters: `id`, `search` (neighbour system ID or IP address), `device` (device id),
`port` (port id), `ifIndex`, `state`, `neighborSystemId`, `neighborIpAddress`.

`routing.viewAll` lists every adjacency, `routing.view` only the adjacencies on
devices or ports the user can access, the same as the web IS-IS page.

Fetching one adjacency with both relationships included:

```curl
curl -H 'Authorization: Bearer YOURAPITOKENHERE' \
  'https://librenms.example.com/api/v1/routing/isis-adjacencies/1?include=device,port'
```

```json
{
  "data": {
    "id": "1",
    "type": "isis-adjacencies",
    "attributes": {
      "index": "1",
      "ifIndex": "2",
      "circuitAdministrativeStatus": "on",
      "state": "up",
      "neighborSystemType": "L2",
      "neighborSystemId": "1921.6800.1002",
      "neighborPriority": "64",
      "lastUpTime": "1183720",
      "neighborAreaAddress": "49.0001",
      "neighborIpAddressType": "ipv4",
      "neighborIpAddress": "10.21.0.2"
    },
    "relationships": {
      "device": {
        "links": { "related": "https://librenms.example.com/api/v1/routing/isis-adjacencies/1/device" },
        "data": { "id": "3", "type": "devices" }
      },
      "port": {
        "links": { "related": "https://librenms.example.com/api/v1/routing/isis-adjacencies/1/port" },
        "data": { "id": "12", "type": "ports" }
      }
    },
    "links": { "self": "https://librenms.example.com/api/v1/routing/isis-adjacencies/1" }
  },
  "included": [
    { "id": "3", "type": "devices", "attributes": { "hostname": "core1.example.com" } },
    { "id": "12", "type": "ports", "attributes": { "name": "Gi0/1", "operationalStatus": "up" } }
  ],
  "links": { "self": "https://librenms.example.com/api/v1/routing/isis-adjacencies/1?include=device,port" },
  "jsonapi": { "version": "1.1" }
}
```

`lastUpTime` is the device's uptime in seconds at the moment the adjacency last
came up, not a wall-clock time. Numeric attributes are returned as JSON strings,
the same as elsewhere in v1.

## Errors

Errors are returned as a [JSON:API error document](https://jsonapi.org/format/#errors)
with an `errors` array:

```json
{
  "errors": [
    {
      "status": "403",
      "title": "Forbidden",
      "detail": "You do not have the necessary permissions to access this resource."
    }
  ]
}
```

| Status | Cause                                                              |
|--------|--------------------------------------------------------------------|
| 400    | An unsupported or invalid query parameter.                         |
| 401    | Missing or invalid bearer token.                                   |
| 403    | The user lacks `api.access` or the permission for this action.     |
| 404    | Unknown endpoint or record, or the v1 API is disabled.             |
| 405    | The endpoint does not support the method.                          |
| 406    | `Accept` only lists the JSON:API media type with unsupported parameters, such as `ext`. |
| 415    | A request body that isn't `application/vnd.api+json`, or has parameters other than `profile`. |
| 422    | The request body failed validation.                                |
| 429    | Rate limit exceeded.                                               |
| 503    | A required service, such as the database, is unavailable.          |

Other statuses use the HTTP reason phrase as `title`. Server errors have a
generic `detail`.

A `400` names the query parameter in `source.parameter`:

```json
{
  "errors": [
    {
      "status": "400",
      "title": "Bad Request",
      "detail": "Unsupported filter: color",
      "source": { "parameter": "filter[color]" }
    }
  ]
}
```

A validation failure has one entry per failed rule, and `source.pointer`
names the attribute:

```json
{
  "errors": [
    {
      "status": "422",
      "title": "Unprocessable Content",
      "detail": "The name field is required.",
      "source": { "pointer": "/name" }
    }
  ]
}
```

### Health

`GET /api/v1/health` is public so it can report a failure even when
database-backed token authentication is unavailable. Its response is
deliberately generic: it does not identify dependencies or include exception
messages, application details, or user information. Requests are limited to
60 per minute per client.

A healthy response returns HTTP 200:

```json
{
  "meta": {
    "status": "healthy"
  }
}
```

An unavailable dependency returns a generic HTTP 503:

```json
{
  "errors": [
    {
      "status": "503",
      "title": "Service Unavailable",
      "detail": "A required service is unavailable."
    }
  ]
}
```

### System

`GET /api/v1/system` requires a bearer token. It returns application
identity and selected table row counts:

```json
{
  "meta": {
    "application": {
      "name": "LibreNMS",
      "version": "26.7.0"
    },
    "statistics": {
      "devices": 42,
      "ports": 512,
      "sensors": 1024
    }
  }
}
```

If the database is unavailable during authentication or while gathering
statistics, the endpoint returns the same generic JSON:API 503 error used by
the health endpoint. Database connection details are never included.
